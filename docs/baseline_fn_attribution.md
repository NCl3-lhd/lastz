# baseline 漏检归因（simHuman–simMouse，无旁系真值）

2026-11-02。问题：baseline 在无旁系真值上 recall 约 0.709，没召回的 29% 是什么。

## 1. 方法

- 脚本：服务器 `scripts/fn_attr.py`；自测 `scripts/fn_attr_selftest.py`（合成数据，类别计数精确符合预期，段特征与朴素循环逐对一致）。
- 输入：
  - 真值：`data/derived/simMammals/truth/simHuman-simMouse.noparalogy.maf`，两端 1:1，共 99,958,410 对。
  - 预测：`runs/nl_simHuman-simMouse_..._20261031T104720Z/baseline_plain/*.maf`，与 `nlchain_eval_simHuman_simMouse.md` 中 baseline 用的是同一份。
- 结果：`results/fn_attr/baseline_plain_np/`，包括 `report.md`、`summary.tsv`、`examples.tsv`，以及逐对数组 `fn_pairs.npz`（可用于后续分析）。32 进程，墙钟 3.5 分钟，峰值内存 32 GB。
- **核对**：全量精确计算得到 recall 0.70904、precision 0.22762，与 mafComparator 抽样结果（0.709 / 0.228）一致。
- **漏检分类**（碱基对按位置精确比较，同 `--near=0`）：
  - unaligned：真值碱基对的两个碱基都没出现在任何预测里；
  - 错位：至少一个碱基被比对了，但伙伴不对。按"预测伙伴离真值伙伴的最小距离"分档；伙伴在不同染色体上的记为 far。
- **特征**：都在真值块内、按真值列计算。
  - "段"指真值中两行都没有 gap 的连续列。
  - "有种子"：段内存在一个 19 列窗口，两侧都是大写，12of19 的 12 个位置最多 1 个转换。
  - maxsub：段内 HoxD55 最大子段和，小写不罚分，是 lastz 无 gap 延伸分的上界。
  - "可锚"：有种子，且 maxsub ≥ hspthresh 2200。

## 2. 结果

|---|---|---|---|
| 召回 | 70.87M | 0.709 | — |
| unaligned | 6.67M | 0.067 | 23% |
| 错位 ≤10 bp | 9.39M | 0.094 | 32% |

| 错位 100–1000 bp | 2.39M | 0.024 | 8% |
| 错位 1–10 kb | 0.23M | 0.002 | 1% |
| 错位 far（>10 kb 或不同染色体） | 1.51M | 0.015 | 5% |

| 特征 | 召回 | unaligned | 错位 ≤100 | 错位 >100 |
|---|---|---|---|---|
| 真值块 <50 对 | 0.195 | 0.373 | 0.400 | 0.393 |
| 局部一致率 <60% | 0.142 | 0.234 | 0.289 | 0.231 |

unaligned 漏检段（真值块内连续的 unaligned 碱基对）：

- 段长：90% 的碱基对落在 11–200 bp 的段里，没有超过 1 kb 的段；
- 80% 的碱基对所在的段覆盖了整个真值块；
- 平均一致率约 65%，与召回部分相近；
- 85% 的碱基对所在真值块里没有任何可锚段。

## 3. 结论

1. **漏检的主体是错位，不是没找到。** 77% 的漏检碱基对其实已被 lastz 比对，只是伙伴不对。其中 63% 离真值伙伴不超过 100 bp，占真值的 18.3%。只有 6.7% 的真值碱基对是两侧都完全没比对到。
2. **近距离错位（≤100 bp）发生在 indel 密集、短无 gap 段的区域。**
   - 这类碱基对所在的真值块明显更短：<50 对的占 40%，召回部分只占 20%。
   - 所在段的最大子段和更低：<1000 的占 67%，召回部分 18%。
   - 一致率却和召回部分差不多。
   - 这说明问题在于 gap 放在哪里、对角线怎么选，而不是同源信号太弱。在 `--near=0` 下，比对上了但错开几个碱基也算漏检。这部分有多少能靠改打分、gap 罚分找回，又有多少是任何比对器都无法唯一确定的，还没区分。
3. **unaligned 部分符合"种子敏感度不够"。** 漏掉的多是整块的短同源片段（11–200 bp），一致率约 65%。84% 所在的段打不出 12of19 种子，85% 所在的真值块内没有可锚段，即使有锚，也只是 maxsub 超过 2200 的上界。改种子或阈值最多只能救回这 6.7% 中的一部分。
4. **远距离错位（>100 bp，包括 far）共占真值 4.1%，小写比例最高（19.6%，召回部分为 3.6%）。** 这符合比对到重复/旁系拷贝上的情况。
5. 小写在三类漏检里都偏多（9.7–19.6%，召回部分为 3.6%）。软屏蔽碱基不出种子，在无 gap 延伸中也受罚，是次要因素。

## 3b. 近距离错位（≤100 bp）的成因

脚本是服务器 `scripts/fn_shift.py`，复用 `fn_attr.py` 的解析，自测在 `fn_attr_selftest.py check_shift`。结果在同一目录下的 `report_shift.md`、`shift_summary.tsv`、`shift_examples.tsv`。

方法：
- 对每个错位碱基对，取离真值伙伴最近的那个预测伙伴，看它落在哪条对角线上。对角线定义为 tg − σ·qg，σ 表示两行同向或反向。
- 分差：同一预测对角线上连续的错位碱基对合成一个"错位段"，段内逐对比较 HoxD55 得分（预测伙伴减真值伙伴）后求和。
  - 如果只是把同一个 indel 挪了位置，两种比对的 gap 罚分相同，段分差就等于总分差。
  - 其他情况下，段分差不含 gap 罚分。

| 预测对角线 | 占错位 | 段分差 >0 / =0 / <0 | 平移 1–3 bp | 平移 11–100 bp | 周期性 |
|---|---|---|---|---|---|
| 同一真值块里存在 | 26.5% | 0.455 / 0.098 / 0.447 | 58% | 16% | 0.3% |
| 相邻真值块里存在 | 23.4% | 0.479 / 0.151 / 0.370 | 30% | 42% | 5.1% |
| 真值里没有 | 50.0% | 0.493 / 0.054 / 0.453 | 11% | 69% | 2.4% |

到真值无 gap 段边界的距离：

| 组 | 0 | 1–2 | ≤5 合计 | 段长中位数 |
|---|---|---|---|---|
| 召回 | 5.4% | 12.0% | 35% | 40 |
| 错位 | 24.2% | 31.1% | 78% | 16 |

错位段大多为 2–20 个碱基对，>200 的几乎没有。

结论：
1. **错位贴着 indel 发生。** 78% 的错位碱基对离真值 gap 不超过 5 个碱基对，所在无 gap 段的中位长度只有 16（召回部分为 40）。错位是 indel 附近局部路径选择不同造成的，与同源信号强弱无关。
2. **一半是"indel 放在哪"的分歧。** 预测走的是真值里存在的对角线，只是 indel 的位置不同。
   - 同块这一类的平移多为 1–3 bp，错位段只有几个到十几个碱基对。
   - 其中 55% 按 HoxD55 不比真值差（>0 占 45.5%，=0 占 9.8%）。这是打分模型与真实进化史的分歧，改进搜索也救不回来。
   - 另外 45% 的替换得分低于真值（下称 A 类）。**这不等于搜索错误**："gap 罚分相同"只在两者是同一个 indel 换位置时成立。以下两种情形也会被归进 A 类，而 lastz 在自身打分下是最优的：
     - 真值在几个碱基内有一对相互抵消的 indel（如 +2 后 −2），lastz 沿外侧对角线直接走过，省下两次开 gap（≥ 2×400）；
     - 比对末端附近，真值有 indel 后只剩一小段，lastz 继续沿原对角线走或停下，省下一次开 gap。
   - A 类里真正的搜索错误，候选机制有：
     - gapped 延伸以锚点（HSP 中得分最高的 31 bp 窗口中点）为界分成左右两半，各自做 y-drop。lastz 源码注释（github issue 54）记录过：一个 2 bp 的 indel 被拆成两半各 1 bp，于是被放弃，换成错配更多、总分更低的比对；
     - 先前的比对限制了后续延伸的路径（`msp_left_right`/`above_below`）。
   - 两类的比例未测，A 类的可修上限（召回率 +0.038）需要重新计算。
3. **另一半走的是真值里没有的对角线（C 类，占真值 9.2%）。** 平移较大（69% 在 11–100 bp）。成因见 3c。

## 3c. C 类的成因

`fn_shift.py` 增加了第 5–12 节，用 `--anc` 读入 ancestor 真值，用 `--view N` 输出对角线剖面到 `shift_view.txt`。每节都在合成数据上自测通过。

逐项排除的解释：

| 假设 | 检验 | 结果 |
|---|---|---|
| 真值块切分造成的假象 | 不看块号，看 query ±100 bp 内是否有真值碱基对落在预测对角线上 | 只有 11%；48% 在全基因组都找不到 → 排除 |
| 比对到旁系拷贝 / 局部重复 | 预测配对在 ancestor（含旁系）真值中是否成立；两处拷贝的 ±25 bp 一致率与随机对照比较 | 只有 7.1% 成立；一致率分布与随机对照相同 → 排除 |
| 串联重复 | ±10 bp 周期性 | 2.4% → 排除 |
| 比对末端 | 预测伙伴离比对块首尾的距离 | 与 A/B 类相同，71% 在 100–1000 对 → 排除 |

C 类的实际特征（对照组均为召回部分抽样）：

| 特征 | C 类 | 召回部分 |
|---|---|---|
| query ±50 bp 内真值对角线变化 ≥5 次 | 42% | 26% |
| target ±50 bp 内真值无同源碱基 ≥30% | 33% | 11% |
| query ±50 bp 内真值无同源碱基 ≥30% | 30% | 10% |
| 被换上的伙伴碱基在真值中无同源 | 49% | — |
| 预测对角线落在窗口内真值对角线范围之内 | 57% | — |
| 在范围外，但离范围 ≤20 bp | 21% | — |

剖面例子（`shift_view.txt`）中最典型的情形：100–150 bp 内，真值在 +0 → +1 → +9，或 +0 → +1 → +2 → +3 → +7 → +6 → −1 这样的多条相邻对角线之间来回移动，中间还夹着谱系特有插入；lastz 只用一条对角线直穿整段，这条对角线夹在真值那几条之间。

结论：
- C 类不是重复序列，也不是旁系拷贝，而是 **indel 和谱系特有插入都密集的区域里，lastz 用一条"平均"对角线代替了真值的多级 indel 台阶**。
- 在 HoxD55 下，每个 gap 至少罚 430，而这类区域里每段无 gap 同源的替换得分常常不到一次开 gap 的分。按 lastz 的打分，不开 gap 直穿很可能就是最优解，这属于打分模型的局限，不是搜索错误。
- 这条推断尚未用含 gap 罚分的总分直接验证。
- 这种区域在模拟数据里很普遍：召回部分也有 68% 在 ±50 bp 内变化 ≥3 次。错位只是在更密的地方更容易发生。所以 C 类能修回多少，取决于换打分模型（更低的开 gap 罚分，或后验解码）后的实际效果，现在无法估计。

## 3d. 不用真值能否识别高 indel 区域

脚本：服务器 `scripts/fn_region.py`，自测为 `fn_attr_selftest.py check_region`。结果：`report_region.md`、`region_summary.tsv`。运行 3.7 分钟，峰值内存 10 GB。

- 评价单位：baseline 的预测碱基对，按 query 坐标每 10 个取 1 个，只取 query 碱基在真值中有同源的，共 1384 万个。
- 标签来自真值：
  - 高 indel：query ±50 bp 内真值换对角线 ≥5 次，占 23.5%；
  - 近距离错位：占 10.6%，对照组是真阳性（51.2%）。
- 特征只用 lastz 输出和序列，不用真值。

| 特征 | AUC：高 indel vs 其余 | AUC：近距离错位 vs 真阳性 |
|---|---|---|
| gaps50（本条预测比对 ±50 对内开 gap 次数） | **0.719** | **0.654** |
| ident25（本条比对 ±25 对一致率） | 0.497 | 0.334（越低越易错） |
| score25（±25 对平均分） | 0.491 | 0.320 |
| qdepth / tdepth（该碱基被几个预测碱基对重复覆盖） | 0.386 / 0.390 | 0.521 / 0.519 |
| blen（比对长度） / end（离比对首尾距离） | 0.602 / 0.581 | 0.505 / 0.511 |
| lower50（软屏蔽比例） / gc50 | 0.494 / 0.465 | 0.545 / 0.480 |

gaps50 分箱：

| gaps50 | 占比 | 高 indel 比例 | 近距离错位比例 |
|---|---|---|---|
| 0–1 | 15.8% | 4–7% | 2–4% |
| 2 | 21.8% | 11% | 6.5% |
| 3–4 | 45.2% | 27% | 12% |
| 5–7 | 16.9% | 47% | 20% |

gaps50 与 ident25 组合：gaps50 ≥5 且 ident25 >70% 的位置，高 indel 比例 56%；gaps50 ≤1 且 ident25 >70% 的位置只有 4%。

结论：
1. **唯一有用的信号是 lastz 自己在附近开 gap 的密度。** lastz 在高 indel 区虽然 gap 放得不准、数量偏少，但开得还是比别处多。不过 AUC 只有 0.72，属于中等区分力。
2. **一致率能预测"会不会配错"，但不能预测"是不是高 indel 区"**（AUC 0.50 / 0.33）。低一致率区错位多，原因是同源信号弱，不是 indel 多。
3. **只看序列的特征（GC、软屏蔽）没有信号。** 高重复覆盖（qdepth ≥6）反而更少落在高 indel 区，那是重复序列被反复比对的区域。
4. 这些特征有一个先天局限：C 类正是 lastz 把台阶拉成直线、一个 gap 都不开的地方，gaps50 在那里恰好偏低。要更好地识别这类区域，需要比对之外的信号。候选有两个，都还没测：
   - gapped 延伸前 HSP 落在相邻对角线上的分散程度；
   - 比对的后验不确定性，即 pair-HMM 的后验概率，或者近似最优路径的数量。

## 3e. 搜索错误还是打分最优（含 gap 罚分的总分对比）

2026-11-03。问题：A 类（及其余近距离错位）里有多少是 lastz 在自身打分下没找到最优（搜索错误，②），有多少是按 lastz 打分预测本来就不比真值差（①）。

### 方法

- 脚本：服务器 `scripts/fn_path.py`（第一步）、`scripts/fn_anchor.py`（第二步）；`fn_shift.py` 新增 `--save`，把逐对的 A/C 归类存成 `shift_pairs.npz` 交给 `fn_path.py`。结果在 `results/fn_path/baseline_plain_np/`。
- **比较单位是"气泡"**，不是整块：原计划"整块同一 t/q 区间内算真值路径总分"不可行，因为真值在一个预测块的区间里通常不是一条连续路径（块很碎，中间有谱系特有插入、重排）。改为：
  - 在预测块内按路径顺序取"一致碱基对"（该对在真值中成立）。相邻两个一致碱基对 a、b 之间夹着不一致碱基对的，就是一个内部气泡。
  - 预测子路径 = 块内 a→b 的碱基对；真值子路径 = 落在矩形 (ta,tb)×(qa,qb) 内、与块同向的真值碱基对。两条路径端点相同，所以分差 = 真值分 − 预测分 > 0 时，把这段换成真值路径就是一条更高分的合法比对，lastz 一定没找到最优（②）；≤ 0 为 ①。
  - 打分：HoxD55，长 k 的 gap 罚 400+30k，相邻两对之间 t、q 两侧的跳过各算一个 gap，预测与真值用同一公式。
  - 末端气泡（第一个一致碱基对之前 / 最后一个之后）：真值分取从端点沿真值往外延伸（不越过预测末端 100 bp）的最佳前缀分。真值更高时，再看到达最佳点前的回撤是否超过 ydrop 3400，超过的算"被 y-drop 截断"（按设计）。
  - 每个错位碱基对按 fn_shift 选出的预测伙伴碱基对归入其所在气泡。
- 第二步需要每条比对的锚点。lastz 没有现成输出，所以加了一个只用于测量的补丁（不进主线）：设置环境变量 `LASTZ_ANCHOR_LOG` 时，每条保留的 gapped 比对写一行（调用序号、锚点处理序号、坐标、得分、锚点相对比对起点的偏移）。补丁在服务器 `build/lastz_alog/anchorlog.patch`，二进制 `bin/lastz_alog`（HEAD d9db595 + 补丁，sha256 9ac0461b…）。用它按 baseline 参数重跑全部 7 条 query 染色体：`runs/alog_baseline_plain/`。
  - 判定：(a) 锚点在气泡内（真值子路径不经过锚点，而 lastz 路径必经锚点）；(b) 否则，同一次 gapped_extend 调用里更早处理出的另一条比对有碱基对落在气泡矩形内（lastz 的 DP 不能穿过已有比对）；(c1) 都不是，且真值子路径相对起点回撤 > ydrop；(c2) 其余。

### 验证

- 自测 `fn_attr_selftest.py gen_path / check_path`：6 个已知答案用例（indel 挪位 → ②；+1/−1 相互抵消、lastz 直穿 → ①；末端真值继续 → 末端 ②；负链版的 indel 挪位；整块平移；末端先回撤 >3400 再回升 → y-drop 截断）。每个气泡的两条路径分与朴素循环逐个一致，类别全部符合预期。
- 自测 `gen_anchor / check_anchor`：伪造锚点日志，(a)/(b)/(c2) 各一例，判定正确。
- 全量数据：
  - 重算的 shift_summary.tsv 与 11-02 的结果逐字节相同。
  - 每块按 MAF 列重算的分与 `a score=` 一致的块 528,694/528,729。不一致的 35 块全在负链、集中在 chrK:4.155M、chrJ:3.28M 两处重复热点，MAF 分都更低，符合 `--masking=50` 动态掩蔽改了高覆盖 target 碱基的打分。
  - 随机抽 7 个气泡，用独立的朴素脚本重算两条路径分，与 fn_path 完全一致，人工看比对文本也合理。
  - 已跑完的重跑 MAF 与 baseline 逐字节相同，日志行数等于块数；28,378 块中 28,372 块的锚点落在自己的路径上（6 块不在，未查）。
- 资源：fn_shift 4.0 分钟 / 36 GB；fn_path 33 秒 / 6.5 GB；fn_anchor 27 秒 / 19 GB（32 进程）。

### 结果：第一步

错位碱基对按所在气泡分类（碱基对数，括号内占真值）：

| 组 | 搜索错误 ② | 平分 | 打分最优 ① | 末端被 y-drop 截断 | 块内无一致碱基对 | 合计 |
|---|---|---|---|---|---|---|
| A 类（同块对角线） | 6,636 (0.0001) | 5,154 | 2,155,288 (0.0216) | 248 | 32 | 2,167,358 (0.0217) |
| A 类（相邻块对角线） | 8,492 (0.0001) | 6,368 | 1,572,246 (0.0157) | 229 | 26 | 1,587,361 (0.0159) |
| 同/相邻块，段分差 ≥0 | 8,664 | 412,915 | 4,960,817 (0.0496) | 255 | 11 | 5,382,662 (0.0538) |
| C 类（真值中没有的对角线） | 322,852 (0.0032) | 24,844 | 8,797,351 (0.0880) | 4,038 | 2,261 | 9,151,346 (0.0916) |

- A 类 3.75M 中 ② 只有 15,128（0.4%），其中 9,132 在内部气泡、回撤 ≤ ydrop，即"y-drop 本可以走到"的那部分。
- 全部 ② 346,644 中：内部、回撤 ≤ ydrop 188,808；内部、回撤 > ydrop 150,655；末端 7,181。② 气泡偏大（预测不一致碱基对中位数 114，① 为 6），分差中位数 1013。抽查的 ② 例子里有 >100 bp 的长 gap：单个 gap 罚 400+30k，k > 100 时就超过 3400，y-drop 会按设计剪掉。
- ① 的分差中位数 −320（P10/P90 −1433 / −75）。抽查的例子里，真值比预测多开 gap 或 gap 更长，多赚的替换分抵不上罚分。

### 结果：第二步（暂时只有 chrM、chrO）

全量重跑在 3f 之后按要求停掉了，只跑完 chrM/N/O/P（MAF 与 baseline 逐字节相同），chrA/F/L 留下的是没写完的 MAF，不能用；`run_anchor.sh` 也一并停了。chrM/O/P 子集的完整归因见 3f 表中 baseline 一列（② 32,456 对中 (a) 539、(b) 973、(c1) 13,850、(c2) 17,094）。下表是 chrM+chrO 的 ② 气泡（329 个），分类在细分 (c1)/(c2) 之前跑出，此后 (c) 已拆成 (c1)/(c2)：

| 组 | (a) 锚点在气泡内 | (b) 矩形内有更早的比对 | (c) 其他 |

| ② 碱基对（全部错位） | 227 (1.3%) | 529 (2.9%) | 17,351 (95.8%) |

锚点离 ② 气泡 >200 个碱基对的占 67%，与 ① 气泡（73%）相近。锚点约束（机制 (a)）在这两条染色体上几乎不出现。

### 可修复上限

把 ② 全部改成真值路径，并假设其余比对不变（预测碱基对总数 3.11 亿）：

| 修复范围 | recall | precision | F | ΔF |
|---|---|---|---|---|
| baseline | 0.70904 | 0.22762 | 0.34461 | — |
| 全部 ②（346,644） | 0.71251 | 0.22873 | 0.34630 | +0.0017 |

### 结论

1. **A 类几乎全是打分最优（①），不是搜索错误。** 3.75M 中 99.6% 按 HoxD55 + 400/30 预测不比真值差。3b 里"A 类 = 段分差 <0"只看替换分；补上 gap 罚分后，这些位置上真值多付的开 gap 罚分都超过了它多赚的替换分。
2. **整个近距离错位（18.3%）里，搜索错误只占真值的 0.35%，约一半还是 y-drop 按设计剪掉的长 gap。** C 类补上 gap 罚分后也一样：9.2% 中 8.8% 是 ①，支持 3c 的推断（"不开 gap 直穿就是 lastz 打分下的最优"）。
3. **锚点约束不是主要机制**（chrM+chrO 上 ② 的 1.3%），已有比对的限制也只占 2.9%。全量结果待 run_anchor.sh 跑完确认。
4. 因此改进 gapped 搜索（不经锚点的窄带重比对、改锚点选取）在这个数据上最多 ΔF ≈ +0.002，A 类只有 +0.0001。近距离错位要找回，只能改打分模型（gap 罚分、后验解码），而不是改搜索。

## 3f. 试验：锚点改取 HSP 内最长完全匹配段的中点

2026-11-03。想法：最长的连续完全匹配段落在真同源对角线上的把握最大。锚点放在那里，应能减少"HSP 跨过 indel、锚点落在错位一侧"的情况，也就是 3e 的 (a) 类。

### 实现

- 新选项 `--anchorpeak=window|run`（`src/gapped_extend.c` 的 `segment_peak`，选项在 `src/lastz.c`，开关在 `src/gapped_extend.h`）。默认 `window`，与原行为相同。
- `run` 的规则：在整条 HSP 上找最长的连续完全匹配段（大小写不分，只算 ACGT），取其中点作锚点。有多段等长时，取中点离原 31 bp 窗口峰最近的；仍相同则取靠左的。

### 验证

- VM 上 gcc 11 `-Werror` 构建通过；`make base_tests` 19/19 SUCCESS（默认模式）。
- 手工例子：HSP 内有一段带转换的 C/G 区（31 bp 窗口分最高，但最长完全匹配 ≤9）和一段 20 bp 的 A/T 完全匹配。`window` 把锚点放在 165（C/G 区内），`run` 放在 221，正是 20 bp 段的中点。
- 在 pseudocat/pseudopig 上，默认模式与 3e 用的测量二进制输出逐字节相同（MAF 与锚点日志都相同）；`run` 模式下 14 条比对相同，锚点位置变了。

### 结果：chrM/O/P 子集

真值只保留 query 在这三条染色体上的块，共 903.7 万对。脚本 `results/anchorpeak/eval_subset.sh`，结果在 `results/anchorpeak/{baseline,run}/`。服务器二进制 `bin/lastz_ap_alog`（HEAD d9db595 + `build/lastz_ap_alog/{anchorpeak,anchorlog}.patch`），重跑目录 `runs/ap_run_baseline_plain/`。

| 指标 | baseline | `--anchorpeak=run` | 差 |
|---|---|---|---|
| recall（精确） | 0.700677 | 0.700704 | +0.000027（+248 对） |
| precision | 0.243927 | 0.243921 | −0.000006 |
| F | 0.361875 | 0.361872 | −0.000003 |
| 搜索错误 ② 碱基对 | 32,456 | 32,502 | +46 |
| 其中 (a) 锚点在气泡内 | 539 | 572 | +33 |
| A 类 ② | 1,284 | 1,287 | +3 |
| 锚点不在自身路径上的块 | 17 / 45,230 | 69 / 45,231 | |
| user CPU 秒（M / O / P） | 1175 / 853 / 1520 | 1203 / 906 / 1510 | 在服务器负载波动范围内 |

结论：

1. **没有可测的效果。** F 差 −0.000003，(a) 类反而略增（539 → 572），整体与 3e 测出的上限一致：(a) 类本身只有 ② 的约 1–2%。
2. 对 (a) 类的解释需要修正：这些情形不是"锚点落在 HSP 错位的那一半"。换成最长完全匹配段，锚点照样落进气泡。也就是说，锚点所在的那段 HSP 本身就在一条局部高分、但与真值不同的对角线上，挪锚点解决不了。
3. 代码已撤销（未提交），全量 `run` 重跑已停（只跑完 chrM/O/P），不做 mafComparator 评测。补丁留在服务器 `build/lastz_ap_alog/anchorpeak.patch`。

## 3g. 预测量：窗口内带 gap 局部比对选锚点

2026-11-03。想法：找到最高分 31 bp 窗口后，在窗口附近做带 gap 的左右延伸，取左右前缀和最优的点作锚点，让锚点落在窗口内最优的带 gap 路径上（针对"窗口里藏着 indel"的情形）。先不改 lastz，用 Python 在已有的锚点日志上复现，量能修多少。

### 方法

- 脚本：服务器 `scripts/fn_anchorbox.py`，自测 `fn_attr_selftest.py check_anchorbox`。
- 框：以原锚点为中心，t 偏移 i ∈ [−15, 15]（即原 31 bp 窗口，原锚点是其中点）；q 沿比对方向偏移 j，|j − i| ≤ band。
- 框内做 HoxD55 + gap 400/30 的局部比对（Gotoh，起止自由），即 F(c)+B(c) 最大的格子所在的路径。回溯这条最优路径，取最长无 gap 段的中点作新锚点；等长取 |i| 最小的。
- 数据：chrM/O/P 的 baseline 子集（`results/anchorpeak/baseline/`），共 45,230 块有锚点。band 取 10 和 3，结果完全相同。
- 验证：
  - 自测两例：两侧完全相同时新锚点为 (0,0)；窗口内缺 2 个碱基时新锚点为 (7,5)，即较长段的中点，路径分 = 29 个匹配 − 460。
  - 全量运行中，每条回溯路径都按 fn_path 的公式重算，结果等于 DP 最优分（脚本内 assert）。
  - 10 秒，2 GB。

### 结果

(a) 类搜索错误气泡（锚点在气泡内，3e 第二步）：

| | 气泡数 | 错位碱基对 |
|---|---|---|
| 全部 | 8 | 539 |
| 真值经过锚点周围的框（必要条件） | 1 | 0 |
| 新锚点是真值碱基对 | 0 | 0 |

全部有锚点的块，原锚点与新锚点是否为真值碱基对（块数）：

| | 新=否 | 新=是 |
|---|---|---|
| 原=否 | 38,048 | 1 |
| 原=是 | 5 | 7,176 |

只看真值经过框的块：原锚点已是真值碱基对的 7,181/7,276（98.7%）；新方法从错变对 1 块，从对变错 5 块。

### 结论

1. **这个方法救不了 (a) 类。** 8 个 (a) 气泡里，7 个的真值路径根本不经过锚点周围 31 bp × ±10 对角线的框。锚点所在的那段 HSP 落在真值没有同源的地方（谱系特有插入一类），窗口内怎么选点都碰不到真值。这与 3f 的观察一致。
2. **原锚点已经很可靠。** 只要真值经过框，原规则的锚点 98.7% 已落在真值碱基对上；新方法净少 4 个。
3. 结合 3e、3f：锚点选取这个方向在本数据上没有改进空间，不再继续。

## 4. 限制

- 段、种子、锚距都局限在单个真值块内。真值块很碎（198 万块，大多 <200 对），而 lastz 的 gapped 延伸可以跨越真值块。所以连召回部分也有 60% 的碱基对"段内无种子"。这些特征只能作组间对比，不能当作"lastz 能否在此处起锚"的判据。
- maxsub 是上界：没有考虑 x-drop 的提前终止、动态掩蔽（`--masking=50`）以及小写罚分。
- 只看了一个物种对（距离 0.501）。
