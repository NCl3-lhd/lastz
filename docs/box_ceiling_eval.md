# 未比对真值的框内找回上限（simTest，当前最佳配置）

2026-11-05。问题：在当前最佳配置下，完全没被比对的真值碱基对还剩多少？其中多少落在相邻两条比对之间的共线框里？也就是"框内找回"（链内桥接、框内无种子 DP）最多能给 F 加多少。

## 1. 设置

- 输入：`runs/tune/rl_r400_8`，即 G3a（`--nlchain --inner=2000 --gappedthresh=2000`）+ `--gap=500,30` + `--realign=400,8`，simTest 10 个物种对共 20 个作业（`realign_ksw2_eval.md` §8.3）。
- 真值：`data/derived/simTest/truth/<t>-<q>.noparalogy.maf`，两端 1:1。
- 第一步：`scripts/fn_attr.py`，与 `baseline_fn_attribution.md` 相同。运行脚本是 `results/fn_attr/rl_r400_8_np/run.sh`，每个物种对的结果在 `results/fn_attr/rl_r400_8_np/<pair>/`。
- 第二步：新脚本 `scripts/fn_box.py`，运行脚本 `run_box.sh`，每个物种对输出 `box_report.md`、`box_summary.tsv`、`box_pairs.npz`。汇总用 `scripts/fn_box_report.py`，结果在 `results/fn_attr/rl_r400_8_np/box_all.md`。
- 资源：fn_box 跑 10 对合计 28 s（16 进程）；fn_attr 跑 10 对合计几分钟。

### 框的定义（`fn_box.py`）

- 对象：unaligned 漏检碱基对，即两个碱基都没被任何预测比对的真值碱基对，fn_attr 的 cat==1。
- **严格框**：把预测碱基对按 query 坐标排序，取真值碱基对 (tg, qg) 在 query 上左右最近的两个预测碱基对 L、R。满足以下全部条件，就算在框内：
  - L、R 都与 qg 在同一条 query 染色体上，也都与 tg 在同一条 target 染色体上；
  - L、R 的方向相同，并且与真值碱基对的方向相同；
  - 共线：方向为 + 时 tL < tg < tR，为 − 时 tR < tg < tL。

  target 轴按同样的方法再判一次，两轴取并。
- 框尺寸：dq = qR − qL − 1，dt = |tR − tL| − 1，size = max(dq, dt)。按定义，框内 query 一侧的碱基全部没被比对。
- **宽松框**：只把与真值同向的预测碱基对当作邻居，也就是跳过夹在中间的反向比对。这样得到的框里可能夹着反向比对。
- **上限**：假设框内的 unaligned 真值碱基对全部被正确找回，并且不引入任何假阳性。即 recall 分子加 x，precision 的分子、分母各加 x。

## 4. 结论

1. **unaligned 仍是远缘对的主要漏检之一。** 10 对平均占真值 6.75%，随距离迅速增大：Mouse-Rat 0.4%，Human-Mouse 4.9%，Cow-Rat 16.3%。Cow-Rat 的漏检里 42% 是 unaligned（fn_attr 报告）。
2. **框内找回的上限可观，而且集中在远缘对。** 严格框全部找回时，平均 ΔF +0.025，宽松框 +0.032。只取不超过 5 kb 的框，严格框也有 +0.021。远缘的 Cow-Rat 为 +0.051～+0.080，Mouse-Rat 只有 +0.002。作为对比，`--realign` 带来 +0.015。这些都是"零假阳性、全部找回"的上限，实际能拿到的只是其中一部分。
3. **找回的难度在于：框大、不方正、同源稀疏。**
   - 81% 的框内碱基对所在框为 201 bp–5 kb，只有 5% 在 200 bp 以内；
   - 86% 的框对角线偏移超过 100 bp，即框里夹着长的谱系特有插入或缺失；
   - 88% 所在框的同源填充率低于 0.5，框里一半以上是非同源序列。

   所以"两端固定、全局比对整个框"不合适：会把大量非同源碱基对强行配上，precision 先掉。需要的是框内的局部比对，或允许长 gap 的比对，加上随框面积变化的分数门槛。
4. **信号弱，但不是没有。**
   - 框内碱基对所在无 gap 段的 maxsub，60% 低于 1000，91% 低于 2000。这解释了为什么 `--inner`（7-mer 种子，HSP 门槛 2000）找不回它们：单个无 gap 段的分到不了门槛。
   - 一致率分布与宽松框外的相近（60–70% 为主）。
   - 能否找回，取决于框内带 gap 的路径总分能否在框面积对应的随机背景之上显著。这一点没测。
5. **块内框为 0。** 这是定义上的必然结果：块内要出现"t、q 两侧都未比对"的区域，需要背靠背的插入和删除，而 lastz 和 `--realign` 都不产生这种路径。块内的问题属于错位，不属于 unaligned。
6. 宽松框比严格框多出 16% 的 unaligned，对应左右邻居方向不同的情形，多半是框中间夹着一条反向比对（真的小倒位，或假阳性）。做桥接时要决定是否跨过它们。

## 5. 限制

- 只测了 simTest（调参集）。这是上限，没有估计找回时引入的假阳性，也没有估计 indel 放置的误差（`--near=0` 下，找回的碱基对还要放对位置才算 TP）。
- 框按"最近的预测碱基对"定义，不区分比对是否属于同一条链。实际桥接只连同一条链上相邻的比对，可能比这里的框更少。框内的假阳性比对会把框切碎，也可能让这里的数字偏低。两个方向的偏差没有分开。
- 多个预测碱基对共享同一个 query 坐标时（qMul 约 0.005），只取排序后最近的一个。
- maxsub、一致率都只是按真值块内的无 gap 段算的代理指标，不是框内最优路径的分。

## 8. 可达量预测量：框内递归局部比对（2026-11-05）

### 8.1 方法

- **取框不用真值**，只用预测本身。把预测碱基对按 (q, t) 排序，相邻两个碱基对 a、b 满足以下条件时，它们之间就是一个框：
  - 同一条 query 染色体、同一条 target 染色体、同方向；
  - dq ≥ 1、dt ≥ 1，且共线；
  - max(dq, dt) ≤ 5000。

  只看 q 轴。框内 query 碱基全部未被比对。方向为 − 时，框内的 q 取反向互补。
- **框内比对**（`build/boxalign/boxalign.c`，二进制 `bin/boxalign`）：
  - Gotoh 局部比对，HoxD55，长 k 的 gap 罚 O + E·k，不允许插入紧接删除；
  - 在框里取最优局部比对，分数 ≥ Tmin（1000）就接受，再在它左下、右上两个子框里递归，所以结果共线、互不重叠；
  - 比对时序列一律按大写处理，不考虑软屏蔽。
- **门槛离线筛选**（`scripts/fn_boxalign.py`）：
  - `abs:T`：分数 ≥ T。子框的最优分不超过父框，所以筛选结果与直接用 T 运行等价。
  - `area:c`：分数 ≥ c + ln(子框面积)/λ，并且所有祖先比对也要通过。λ 是 HoxD55 在两基因组碱基组成下的无 gap λ，约 0.0087，只当缩放尺度用。随机 1–5 kb 框的 ln(area)/λ 约为 1200–1400。
- **评测**：
  - 新增碱基对的 query 碱基原先都没被比对，所以 recall 分子加上新增 TP，precision 分子加新增 TP、分母加新增碱基对数。
  - 假阳性分为四类：q 碱基在真值中无伙伴（q 无同源）、错位 1–10、错位 11–100、其余。
- 输入、真值同 §1。gap 罚分取 400/30 和 400/8 两组，即 lastz 延伸用的值和 `--realign` 用的值。运行脚本 `results/boxalign/run.sh`，每组结果在 `results/boxalign/rl_r400_8_g{400_30,400_8}/<pair>/`，汇总在 `results/boxalign/report_all.md`（由 `scripts/fn_boxalign_report.py` 生成）。
- 资源：20 个作业合计墙钟 59 s（48 进程）。每个作业单进程峰值内存不到 1 GB。

### 8.2 验证

- **`boxalign_test.py`**（`build/boxalign/`）：用全表 Python 实现做参考，参考实现与 C 版用同样的平局规则，但代码结构独立。
  - 覆盖 3 组参数（400/30、400/8、100/5），各 300 个随机框，框里种入带替换和 indel 的同源片段。
  - 1,016 条比对的输出逐行相同；每条比对按 cigar 重算的分等于输出分，cigar 恰好消耗所报区间；没有背靠背 gap；同一框内的比对共线、不重叠。
  - 变异检验：把 gap 的平局改为优先打开、把对角线的 `> 0` 改为 `≥ 0`、把 F 的平局改为优先 F，三处各改一处，都被测试报出。

- **`fn_attr_selftest.py gen_boxalign / check_boxalign`**，构造 4 个框：

### 8.4 结论

1. **可达的收益约为上限的五分之一。** 最好的一档（400/30，area 0；abs 1500 与之相差 0.0002）平均 ΔF 为 +0.0047，10/10 个物种对都提高，远缘对最多（Cow-Rat +0.012，Mouse-Rat +0.001）。§4 算出的零假阳性上限是 +0.025（严格框）或 +0.021（≤5 kb）。曲线在 abs 1500–2000、area 0–500 之间很平，门槛不敏感。门槛是在调参集上选的，这一点要注意。
2. **限制收益的是新增碱基对的精度，不是找不到。**
   - 只有约 0.52 的新增碱基对是对的。即使只留 8000 分以上的比对，精度也只有 0.59。
   - 假阳性中约 56% 的 q 碱基在真值里根本没有同源：局部比对穿过了框里的谱系特有序列，用错配把它们连起来了。这与 §3.3 中"88% 的框同源填充率 <0.5"一致。
   - 另有约 37% 是同源但错开了 1–100 bp，这是 `--near=0` 口径下的放置误差。
3. **框内 gap 延伸罚分不能低。** 400/8 的局部比对更容易一路连过非同源序列，新增精度降到 0.35–0.44，最好也只有 +0.0013。这与 `--realign` 的结论相反：重比对的两端固定在原路径上，路径不会越出同源区；局部比对没有这个约束。
4. **还能提高多少，要看能不能去掉"q 无同源"这一半假阳性。** 可能的手段（都没测）：
   - 对新增比对按窗口打分修剪，切掉低分的内部片段；
   - 用更严的打分或 x-drop 把一条比对拆成多段；
   - 让新增比对也经过 `--realign`，修掉一部分错位。

   粗算：找回的 TP 不变、新增精度从 0.52 提到 0.7 时，Cow-Rat 的 ΔF 从 +0.0118 变为约 +0.018，约为原来的 1.5 倍；按同样的比例，平均 ΔF 约为 +0.007。
5. **与其他方向对比。** +0.005 和 `--gap=500,30`（+0.004）、`--inner`（+0.009）的单项收益在同一量级，小于 `--realign` 的 +0.015。做进 lastz 要新增"链内相邻比对之间的框内比对"一步，改动量中等。

### 8.5 限制

- 只取 q 轴相邻、≤5 kb 的框，没有试 t 轴、宽松框、更大的框。
- 新增比对没有经过 `--realign`。在真实流程中，它们会在 realign 之前加入，错位类假阳性可能减少一部分。
- 比对按全大写处理，忽略了软屏蔽；lastz 实际的计分可能不同。
- 只在 simTest 上测，门槛也在 simTest 上选。

   - (a) 对新增比对做窗口修剪；
   - (b) 把新增比对按 `--realign=400,8` 的方式重比对后再评测；
   - (c) 加入 t 轴取框和宽松框。

   如果合计能让平均 ΔF 明显超过 +0.005（比如到 +0.008 以上），再写 lastz 内的实现方案。

### 10.5 结论

1. **原版接 chainNet 后，最优点是 `--inner=2000`。**
   - 相对不加 `--inner`，F_np +0.009、F_anc +0.012，9/10 对提高，远缘对提高最多（Cow-Rat +0.023）。
   - 门槛再降，recall 和 precision 同时下降：1000 时 F_np 0.7026，比不加 `--inner` 还低；700 时 0.6855；500 时 0.6810。10/10 对都下降，近缘对下降最多（Mouse-Rat 在 700 门槛下比 2000 门槛低 0.048）。
   - 原因推测：低门槛插值产生的大量重复比对，在 axtChain 中连成了高分的假链。这些假链在 chainNet 的 1:1 选择中排挤掉了真链，所以 recall 也降了。这一点没有核实。
2. **门槛降到 2000 以下，原版的 lastz 开销不可接受。** 1000 门槛的 CPU 是 2000 门槛的 27 倍，500 门槛是 76 倍，输出也增加到 26 倍。
3. **nlchain 能用更低的门槛，而原版不能。** nlchain 只在 1:1 主路径的相邻锚点之间插值，插值 HSP 还要再串一次链，所以把门槛降到 1000 仍然有益（+0.005），CPU 只增加约 10%。原版没有这层约束，插值会扩散到全基因组，2000 已经是它能用的下限。
4. **最终对比（各自最优）：**
   - nlchain 1000/1000：F_np 0.7665、F_anc 0.7558；
   - 原版 2000/2000 + chainNet：F_np 0.7294、F_anc 0.7312；
   - nlchain 高出 +0.037 和 +0.025，10/10 对 F_np 都更高；
   - lastz CPU：nlchain 2,318 s，原版 5,140 s，这还没算 chainNet 的开销。
