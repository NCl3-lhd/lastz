# nlchain 与 LASTZ+chainNet 的 precision 差距：根因与方案

日期：2026-11-01。数据：Alignathon simTest，10 个物种对。只用 simTest；16 个最终测试物种对不参与本分析。相关文档：`docs/nlchain_progress.md`（§6、§8）、`docs/nlchain_tune_testset.md`（§3.5、§5）、`docs/nlchain_design.md`（§7）。

## 0. 结论

1. **"gapped 延伸越出段边界"不是主因**。越出段框的碱基对有 58% 是真阳性。按段框裁剪后 F 反而下降：边距为 0 时从 0.7085 降到 0.6889，边距 1000 时为 0.7011。
2. **根因是 nlchain 缺少 chainNet 流程里"拆块重新串链、丢掉低分碎片链"这一步。** lastz 的 y-drop gapped 比对总分达标（≥ gappedthresh），但内部和尾部常带有 50–1000 bp 的错位片段。这些片段所在的 query 或 target 碱基，另一条比对已经对在正确的对角线上。
   - 在 baseline 里，axtChain 把比对拆成无 gap 块后重新串链，这些片段会落进单独的小链，再被 chainAntiRepeat 的默认分数下限（5000）删掉。
   - nlchain 直接输出 gapped 比对，没有这一步。
   - 证据：把 nlchain 的输出送进 axtChain 再加 5000 的链分下限，删掉的 428 万个碱基对里 95.4% 是假阳性。precision 从 0.6707 升到 0.7022，recall 只降 0.0025，F 为 0.7247，超过 chainNet 的 0.7205。
3. **方案 A（已确认，2026-11-02）**：在 nlchain 模式下，gapped 之后加一步"按无 gap 块重新串链，加链分下限"。不改代码的模拟结果：
   - noparalogy 真值：F 0.7247，比 nlchain 高 0.016，比 chainNet 高 0.004，9/10 个物种对不低于 chainNet；
   - ancestor 真值：F 0.7167，比 nlchain 高 0.011，比 chainNet 低 0.002；
   - 链化本身的 CPU 只占 lastz 的约 0.4%。
4. **用户决定（2026-11-02）**：方案 A 在 `--nlchain` 下默认开启；次级链按用途选（§3.1）。
   - 只要 1:1 直系同源：用默认参数。
   - 需要旁系同源：加 `--nlchainsecondary=<4h>,1,0.9`。
   - 实施方案见 `docs/nlchain_rechain_plan.md`。

## 1. 方法

- **输入**：
  - nlchain 用当前默认值的输出 `runs/tune/nl_step5default/`，含段表 `.segs.tsv`；
  - 对照为 `runs/tune/chainnet_medium3000/`。
- **逐碱基对归因**：服务器上的 `scripts/prec_attr.py`。
  - noparalogy 真值两端 1:1，所以每个 query 碱基最多只有一个真值伙伴，可以精确判定每个预测碱基对的真假。
  - 预测碱基对按出现次数计，recall 用去重后的真阳性。
  - 与 mafComparator（`--samples=10000000 --seed=1`）逐位一致。例如 Cow-Dog 上 nlchain 的 P 都是 0.769809，chainNet 都是 0.804675，R 也一致；10 个物种对的平均值与 `nlchain_tune_testset.md` §3.1 相同。
  - 需要 numpy，服务器的系统 Python 没有，装在 `build/pylib`（`pip install --target`）。
- **不改代码的模拟**：
  - 先把输出转换成 chain 或 MAF；
  - 再用 `prec_attr.py` 做 noparalogy 真值上的精确评测；
  - 最终数字再用 mafComparator 在两份真值上各评一次（`scripts/eval_sim.sh`），noparalogy 上两者一致。
- 下文的数字除特别注明外，都是 10 个物种对的**碱基对总和**（P/R/F 为 10 个物种对的平均）。

## 2. 假阳性的分解

### 2.1 总量

| | 预测碱基对 | 真阳性 | 假阳性 | P | R | F |
|---|---|---|---|---|---|---|
| nlchain（默认） | 89.36M | 60.98M | 28.38M | 0.6707 | 0.7517 | 0.7085 |
| chainNet medium/3000 | 86.42M | 60.84M | 25.58M | 0.6930 | 0.7505 | 0.7205 |
| 差 | +2.94M | +0.14M | **+2.81M** | | | |

**只在一方出现的碱基对**：
- nlchain 独有 5.90M 个，其中真阳性只有 0.61M（10%）；
- chainNet 独有 2.96M 个，其中真阳性 0.48M（16%）。
- 两者的假阳性之差（5.29M − 2.48M）正好等于上表的 2.81M。

### 2.2 nlchain 独有的 5.29M 个假阳性

| | 冗余（该 query 或 target 碱基在 nlchain 输出里另有真阳性碱基对） | 非冗余 |
|---|---|---|
| 纯度 ≥ 0.5 的段 | **3.14M** | 1.10M |
| 纯度 < 0.5 的段（"假段"，共 1,787 段） | 0.60M | 0.45M |

- **冗余假阳性占 71%**。也就是说，大部分多出来的假阳性所在的碱基，nlchain 自己的另一条比对已经对对了。
- 只把这些冗余假阳性删掉（oracle），nlchain 的 P 是 0.7074，R 不变，F 是 0.7287。用同样的口径算 chainNet，P 只有 0.7014。
- 假段的贡献较小：假段上的假阳性共 5.02M 个，其中 3.97M 个 chainNet 也同样输出了，属于两者共有的错误。

### 2.3 按位置（相对所属主路径段的 q/t 框）

| | 碱基对 | 假阳性 | 其中重复使用碱基的假阳性 |
|---|---|---|---|
| 段框内 | 81.96M | 25.27M（89%） | 5.62M |
| query 越出段框 | 7.31M | 3.05M | 1.18M |
| 仅 target 越出 | 0.09M | 0.07M | 0.06M |

- 越出段框的碱基对有 58% 是真阳性：y-drop 越过 HSP 边界延伸出去的部分，大多是真同源。
- 裁剪模拟（只保留离段框不超过 m bp 的碱基对）：

| m | P | R | F |
|---|---|---|---|
| 0 | 0.6799 | 0.6991 | 0.6889 |
| 200 | 0.6753 | 0.7138 | 0.6935 |
| 1000 | 0.6712 | 0.7345 | 0.7011 |
| 5000 | 0.6708 | 0.7494 | 0.7076 |

  任何边距都会降低 F，所以否定原假设。

### 2.4 假阳性的性质（离真值伙伴的距离）

每个假阳性碱基对 (t, q)，取 q 的真值伙伴与 t 的距离、t 的真值伙伴与 q 的距离，两者中的较小值。

| 距离 | nlchain | chainNet | 差 |
|---|---|---|---|
| ≤ 10 bp | 7.35M | 7.30M | +0.05M |
| 10–100 bp | 8.26M | 7.25M | +1.01M |
| 100–1000 bp | 4.74M | 2.30M | **+2.45M** |
| 1–10 kb | 0.62M | 0.34M | +0.28M |
| 更远 | 0.64M | 0.95M | −0.32M |
| 两碱基在真值里都无同源 | 6.77M | 7.44M | −0.67M |

nlchain 多出来的假阳性集中在偏离真值 10–1000 bp 的错位上，位置在大 indel、串联重复和断点附近。这与"同一区域已有正确比对，又多出一条偏移比对"一致。另外，nlchain 有 target 端重复使用的假阳性 5.27M 个，chainNet 为 0。

### 2.5 chainNet 流程是在哪一步去掉这些假阳性的

把 nlchain 的原始 MAF 送进与 `chainnet_pair.sh` 相同的 kent 流程（`scripts/chainsim_pair.sh`），分步评测：

| 处理 | 预测碱基对 | P | R | F_np |
|---|---|---|---|---|
| nlchain 原始输出 | 89.36M | 0.6707 | 0.7517 | 0.7085 |
| 只跑 axtChain（`-minScore=0`，不加下限） | 89.05M | 0.6726 | 0.7512 | 0.7094 |
| axtChain + 链分 ≥ 3000 | 85.38M | 0.7005 | 0.7500 | 0.7242 |
| axtChain + 链分 ≥ 5000 | 85.08M | 0.7022 | 0.7492 | **0.7247** |
| axtChain + 链分 ≥ 8000 | 84.82M | 0.7035 | 0.7481 | 0.7249 |
| axtChain + 链分 ≥ 12000 | 84.50M | 0.7046 | 0.7465 | 0.7248 |
| axtChain + chainAntiRepeat（不建 net） | 85.28M | 0.7009 | 0.7495 | 0.7242 |
| 完整 chainNet 流程（axtChain `-minScore=3000`） | 83.60M | 0.7104 | 0.7447 | 0.7270 |

- **只做重新串链几乎没有作用**（F 0.7094）。作用来自重新串链之后丢掉低分链。下限取 3000–12000 时 F 只在 0.7242–0.7249 之间变化，结果不敏感。
- chainAntiRepeat 的效果与"链分 ≥ 5000"几乎一样（F 0.7242 对 0.7247）。原因是它的默认 `-minScore=5000` 对所有分数低于 `noCheckScore` 的链都生效，重复序列和低复杂度的调整只会让分数更低。简单模拟的基因组里小写碱基只有约 7%，所以调整项的作用不大。
- nlchain 的 gapped 比对每条都 ≥ 6000（gappedthresh），所以低于 5000 的链**必然是从某条比对上拆下来的碎片**。
  - Cow-Dog 上，4,903 条 nlchain 比对被 axtChain 拆成 15,770 条链，其中 14,791 条低于 5000。
- **被下限删掉的 4.28M 个碱基对**（nlchain 有、"axtChain + ≥5000"没有）：
  - 真阳性只有 0.197M（4.6%）；
  - 91% 的碱基被另一个块重复使用；
  - 89% 在段框内，越界的只占 9%；
  - 位置上，与比对首尾相连的 2.11M 个（真阳性 7%），比对中段 2.17M 个（真阳性 2%）；
  - 片段长度大多在 50–1000 bp：50–200 bp 有 12.0k 段，共 1.28M bp；200–1000 bp 有 6.4k 段，共 2.48M bp。
- **例子**（Cow-Dog，被删掉的链）：
  - `simCow.chr0:4809782-4810401` × `simDog.chr0+:4772391-4773010`，链分 3107，551 个碱基对，真阳性 0。这段 query 有 97% 已被 ≥5000 的链覆盖，与真值伙伴的偏移中位数为 512 bp。
  - `simCow.chr0:4476226-4476593` × `simDog.chr0+:4443600-4444036`，链分 2918，query 97% 被覆盖，偏移 1258 bp。
- **chainNet 的优势就来自这一步**：baseline 的 gapped 比对里同样有这类碎片，只是在 chainNet 流程里被删掉了。nlchain 少的就是这一步，与段的选择无关。这一步删掉的 4.08M 个假阳性，比 nlchain 多出的 2.81M 还多。
- 这也解释了 §3.5 那个诊断为什么只能解释 1/5：块级 1:1 贪心只能整块保留或整块丢弃，碎片却在块内。
- 机制：
  - 跨过一个 k bp 的 indel，lastz 的代价是 400+30k。k 超过约 100 bp 时，这个代价就大于 ydrop=3400，y-drop 延伸只能沿原对角线继续，产生错位的片段；对侧 anchor 延伸出来的比对又覆盖了同一段。
  - lastz 用先前的比对来约束后续延伸（bounding），但这只能防止路径交叉，挡不住平行重叠。

### 方案 A：gapped 之后按无 gap 块重新串链，加链分下限（已确认）

> 下面是最初的设想。2026-11-02 核对 kent 源码后，实施方案改为照搬 axtChain 的代价模型：两侧都有 gap 时用 bothGap 行、重叠按交叉点调整、不限 gap 长度。原因是 nlchain 的 g(d) 只对应 qGap 一行，代价模型不同。详见 `docs/nlchain_rechain_plan.md` §2 和 §5 D1。

**做法**（在 nlchain 模式下，gapped 延伸之后、输出之前）：
1. 把本条 query 两条链上的全部 gapped 比对拆成无 gap 块，块分为替换分之和。
2. 在每个 (target 分区, 链方向) 内做共线链化。
   - 直接复用 nlchain 的正常边：g(d) 用 medium 表，它本来就是 axtChain 的 linearGap medium；K-d 树搜索、maxGap 和 maxDiag 也照用。只用 L 状态，不用跳转。
   - 按分数从高到低依次取链，每个块只用一次，做法同 axtChain 和 §5.4 的次级回溯。
3. 链内相邻的块如果在 t 或 q 上重叠，就在使总分最大的交叉点裁开（同 axtChain 的 `removePartialOverlaps`）。
4. 删掉链分低于 T_chain 的链。T_chain 是新参数，默认 5000；3000–12000 都可以，结果不敏感。是否改成随 hspthresh 缩放，实现时再定。
5. 输出。按难度从低到高有两种做法：
   - 把原比对在被删块处切开，分段输出；
   - 用链的块重建比对。

   两种做法的碱基对相同（交叉点裁剪除外）。

**预期影响**
- 准确度：见上表。recall −0.0025（np）/ −0.0049（anc），precision +0.032（np）/ +0.032（anc）。
- 速度：axtChain + chainAntiRepeat 处理 nlchain 输出共 5.6 s CPU（20 个作业），nlchain 本身是 1,533 s，约占 0.4%。在 lastz 内部实现也应在同一量级，不改变"CPU 约为 chainNet 的 1/1.9"的结论。
- 复杂度：中等偏高。
  - 链化可以复用 `nlchain.c` 的正常边、K-d 树和多次回溯；
  - 新增的工作是：从 lastz 的比对结构（edit script）拆块和回写、交叉点裁剪、一个新参数和单元测试。
  - 风险：模拟用的是 axtChain 本身。自己实现时，取链顺序、两侧都有 gap 时的代价（bothGap）等细节会不同，必须在 simTest 上重跑来确认。

**不改代码的过渡做法**：`lastz --nlchain` 的输出接 `axtChain -minScore=0 | chainAntiRepeat`，这正是模拟用的流程。但这样又回到了"多个程序"，只能临时用。

### 方案 B：方案 A 再加 target 端 net 式去重

- noparalogy F 最高（0.7270，10/10 个物种对不低于 chainNet），但 ancestor F 只有 0.7118，比 chainNet 低 0.007，0/10。
- 它强制 target 端 1:1，会去掉 D 回跳带来的 target 重复使用，与主路径允许回跳的设计冲突。
- 要实现 chainNet 的 gap/fill 层级，是三个方案里最复杂的。
- 相对 A，F_np 只多 0.002，F_anc 少 0.005。**不建议默认开启**；如果以后要 target 端 1:1 的输出，可以做成一个选项。

### 方案 C：只做成对的交叉点裁剪（不重新串链，不设下限）

- 做法：同一 (query, target, 链方向) 内，两条比对只在端部重叠时（一条在 t、q 两维上都排在另一条之前），在最优交叉点裁开。
- 实现最简单，只对相邻比对做局部处理，不需要链化。
- 但只补回约 60% 的差距：F_np 0.7157，0/10 个物种对达到 chainNet。剩下的碎片属于"包含"或平行重叠，成对裁剪处理不了。
- 可以作为 A 的第 3 步，但不能代替 A。

### 已否定

- **按段的 q/t 区间裁剪 gapped 输出**（原 §8 结论 3 的候选）：F 下降，见 §2.3。
- **按块分做 target 端或两端去重**：F 0.7082 / 0.7073，不升。碎片在块内，整块取舍会把对的部分一起删掉。
- **限制 y-drop 越过断点**：与段框裁剪等价或更弱，因为被删碎片 89% 在段框内。没有单独模拟。

## 4. 未解决与下一步

1. 方案 A 已确认，按 `docs/nlchain_rechain_plan.md` 实施。实施步骤、验收线和编码前要确认的设计选择 D1–D6 都在那份文档里。
2. 模拟只覆盖 simTest 的中远缘物种对，近缘物种对没有验证。
3. 假段（纯度 < 0.5）贡献 1.05M 个 nlchain 独有的假阳性，是第二大来源，A 不处理。如果 A 实现后还有差距，再看跳转代价和 T_solo。
