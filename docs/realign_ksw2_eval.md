# 框内全局重比对（ksw2）：lastz 输出块的 gap 重排

2026-11-05。

## 1. 动机

- `baseline_fn_attribution.md` §3e：近距离错位（simHuman–simMouse 上占真值 18.3%）几乎全是"按 HoxD55 + 400/30 打分预测路径不比真值差"，只能靠换打分模型改善。
- `scoring_param_eval.md`：在 lastz 的 gapped 延伸里降低 gap 罚分会让 y-drop 剪不住，比对冲进非同源序列，F 变差。
- 思路：lastz 的输出块已经定好了"在哪里比对"，在块的框内、两端固定做全局比对，"在哪里停"就和"gap 怎么摆"分开了，gap 罚分可以按摆放的需要单独调。

## 2. 实现（服务器 `build/ksw_realign/`，原型，不进 lastz）

| 文件 | 内容 |
|---|---|
| `ksw2.h`、`ksw2_extz2_sse.c`、`ksw2_extd2_sse.c`、`kalloc.[ch]`、`LICENSE.txt` | 从服务器已有的 minimap2 v2.28 源码拷贝（MIT），sha256 记在 `SOURCES.sha256`；不另外下载 |
| `ksw_realign.c` | 驱动：stdin 每行一段（id、target、query、带宽），全局比对，输出分数、CIGAR、最终带宽。q==q2 且 e==e2 时用 `ksw_extz2_sse`，否则用 `ksw_extd2_sse`（与 minimap2 `align.c` 相同） |
| `ksw_ref_test.py` | 自测：随机小例子上与独立写的 Gotoh 全局比对（单/双仿射、带约束）比较分数，并核对 CIGAR 重算与长度 |
| `band_probe.py` | 带边行为探查（§3 第 3 条） |
| `realign_maf.py` | 读 lastz 的两行 MAF，按块切段、调驱动、拼回 MAF |
| `rk_run.sh` | 对 `runs/tune/<输入组>` 的 20 个作业批量重比对，输出 `runs/tune/rk_<tag>/`，带 `.time`、`.done`，可直接用 `eval_tune.sh` 评测 |
| `rk_grid.sh`、`rk_grid2.sh`、`rk_full.sh` | 本文的三批运行 |

`realign_maf.py` 的做法：
- **切段**：在长度 ≥ 11 的无 gap 段中点处切开，相邻切点至少相隔 1000 列。切点是 lastz 路径上的格点，所以每段的两端都固定在原路径上。块首尾坐标、长度、方向都不变。
- **带宽**：w = 原路径在段内的最大对角线偏移 + 16。
- **打分**：HoxD55 与 gap 罚分按同一比例 1/s 取整（四舍五入，0.5 远离 0），s 取满足 ksw2 约束的最小整数。表中给出的都是取整后的有效值（原始单位）。
- **校验**：任一项不过，该作业就失败退出：
  - 每段 ksw 分 ≥ 原路径在同一打分下的分（原路径落在带内，是可行解）；
  - 按 CIGAR 重算的分 = ksw 分，且 CIGAR 恰好消耗两条序列；
  - 输出块去掉 gap 后的序列与输入相同。

## 3. ksw2 的坑（都由自测发现）

1. **`mat[0]` 必须是矩阵最大值。** `ksw_extd2_sse` 核心循环里有 `z = _mm_min_epi8(z, sc_mch_)`（`sc_mch_ = mat[0]`），按 A C G T 次序时，C-C（100）被钳成 A-A（91）。改用 C A G T 次序，驱动检查 `mat[0]` 为最大值。
2. **单仿射不能用 `extd2`。** 两套参数相同时，`extd2` 给出的分与 CIGAR 不一致。改为与 minimap2 一样用 `extz2`。
3. **8 位溢出。** `extz2` 把分值存成 s + 2(q+e) 的 8 位量（`max_sc_ = mat[0] + 2(q+e)`），在 `mat[0]`=25、q+e=54（和 133）时算错。驱动要求 `mat[0] + (q+e) + (q2+e2) ≤ 127`，另外还有 minimap2 的 `(q+e)+(q2+e2) ≤ 127`、ksw2 的 `−min ≤ 2(q+e)`。
4. **带边。** 最优路径碰到带边（|i−j| ≥ w−1）时，分数和 CIGAR 都可能错。`band_probe.py`：错例 100% 碰边，不碰边的全部正确。驱动发现碰边就把 w 改为 2w+16 重算。全部 10 对的 400/8 右对齐运行中，143,296 段里加宽了 2,929 段。
5. **还有一种没查清的不一致**：100/30（s=3，`mat[0]`=33，`mat[0]`+2(q+e)=119，在上述约束之内）有 3 个作业被"CIGAR 重算 ≠ ksw 分"拦下。校验让作业失败，没有输出错误结果；这一档本来就差，没有再查。

自测：`ksw_ref_test.py ./ksw_realign 400`，覆盖 6 组参数 × 3 种缩放 × 左/右对齐，共 14,196 项检查，0 失败。余量 2、3 的窄带用例也全部正确（驱动自动加宽）。

## 5. 结论

1. **框内重比对有效。** 400/8 右对齐相对 lastz 的 G3a + 500/30：F_np +0.0146（0.7463 → 0.7609），F_anc +0.0118（0.7371 → 0.7489），10/10 个物种对两项都提高。相对原先的推荐配置 G3a + 400/30：F_np +0.0187，F_anc +0.0134。recall 和 precision 同时提高（R_np +0.007，P_np +0.022），符合"错位碱基对改对后同时减少一个漏检和一个假阳性"。
2. **gap 延伸罚分在框内应当低得多。** 最优的 E 约 8–9，而 lastz 延伸里 E=30 最好，E=20 已经失控变差。E=0 时 precision 更高，但 recall 降得更多。open 罚分不能低：O 在 400–500 最好，≤300 下降，≤200 明显变差。在框内，"开一个 gap 要贵、开了之后长一点便宜"的打分更接近真值。
3. **双仿射没有收益。** 三组双仿射都不如单仿射 400/8；在单仿射 E 已经很低的情况下，另设一段更便宜的长 gap 没有用处。
4. **indel 右对齐有稳定的小收益。** 每一档的 F_np 都高约 0.003–0.004（10 对上 400/8：0.7580 → 0.7609），近缘对收益最大（Mouse-Rat +0.006）；F_anc 基本不变（−0.0002）。说明 evolver 真值在平分时更常把 indel 放在右侧，这是评测口径上的偏好，不是同源判断更准。
5. **开销小。** 重比对用 Python 驱动，20 个作业合计 152 s CPU，约为 lastz 本身（约 1,600 s）的 9.5%；用 C 实现会更少。
6. **限制**：
   - E 只能按 s 个原始单位为一档（s=8 时为 0、8、16…），E 在 1–7 之间的值测不到；
   - 矩阵取整误差（s=8 时转换分 −25 → −24）；
   - ksw2 还有一种没查清的不一致（§3 第 5 条），现在靠校验兜底。

## 6. 未解决 / 风险

- 只在 G3a + 500/30 的输出上做了重比对。重比对之后，lastz 阶段最好的 gap 罚分可能变了：框内重比对修正了 gap 摆放，lastz 只需要负责"在哪里比对"。没有测 400/30 或其他输入。
- 没有用 `fn_shift` 等脚本分类核实改善具体来自哪类错位（A 类 / C 类）。
- 切段长度（1000 列）、切点所需的无 gap 段长度（11）、带宽余量（16）都没扫过。
- 所有脚本都只在服务器的 `build/ksw_realign/`，本仓库没有副本；本地副本在本次会话的 scratchpad，会话结束后就没有了。
- 只在 simTest 上测过（调参集）。

## 8. lastz 内的实现：`--realign`（2026-11-05）

方案见 `docs/realign_plan.md`（决策项按推荐：通用选项、O/E 必须显式给出、输出分数按 lastz 自身打分重算、不做双仿射、切段常数写死）。代码尚未提交。

### 8.1 实现

| 文件 | 内容 |
|---|---|
| `src/realign.h` / `src/realign.c`（新） | `realignparams`；`realign_aligns()` 原地替换每条比对的 edit script 并按 `score_alignment` 重算分数。切段规则同原型（长度 ≥ 11 的无 gap 段中点，相邻切点 ≥ 1000 列）；每段做带约束的 Gotoh 单仿射全局比对，替换分直接用 `scoring->sub`（不缩放），带宽 = 原路径最大偏移 + 16，路径碰到带边（偏移 ≥ w）就把 w 改为 2w+16 重算；回溯表超过 2^30 格时保留原路径。每段校验"新分 ≥ 原路径分"，整条校验新 script 恰好覆盖原比对，违反即退出。`-Dcollect_stats` 计数 |
| `src/realign_test.c`（新） | 单元测试，`make realign_test`；`--tsv` 模式读原型格式的段做逐段对照 |
| `src/lastz.h` / `src/lastz.c` | 参数（默认关闭）、`--realign=<O>,<E>[,right\|left]`、与 `--nogapped` / `--format=segments` 互斥、调用点（打印之前：重新串链或非 nlchain 的插值之后，`mirror_alignments` 之前）、`debugClockRealign`、统计、`--help` |
| `src/Makefile`、`.gitignore` | `realign` 加入构建；`realign_test` |

平局规则：right 时回溯中优先走 gap、gap 内优先"开"（indel 靠右）；left 时优先走对角线、gap 内优先"延伸"（indel 靠左）。

- 与原型相差 F_np +0.0004、F_anc +0.0005（验收线 ±0.002）。原型有 int8 取整，转换分 −25 → −24。
- 相对不重比对：F_np +0.0150，F_anc +0.0123，10 个物种对全部提高。

计数：78,470 条比对、143,296 段、104,668 段分数提高、加宽 22,119 次；比对列数 1.007 亿 → 1.024 亿。

- **重比对占总时间 11%，不符合方案中"远低于原型 9.5%"的预期。** 原型用 ksw2 的 SIMD 实现，本实现是标量 DP。
- 加宽次数（22,119 次）远多于原型加宽的段数（2,929 段）。E=8 时长 gap 很便宜，带内最优路径常碰边，带宽成倍扩大，可能一直扩到整段矩阵。推测这是主要开销，没有分项测量。

## 9. 未解决 / 风险（lastz 实现）

- **性能**：重比对约占总时间 11%。可选的优化：
  - 测量加宽开销的占比，再决定是否给加宽设上限（例如不超过初始带宽的若干倍）；
  - 改用沿原路径走的带，代替以主对角线为中心的带；
  - 内层循环向量化。
  
  前两项会改变结果，需要重新评测。
